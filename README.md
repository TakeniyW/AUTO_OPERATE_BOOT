# x-batch 使用说明

ixBrowser 多窗口 × Twitter 批量登录（token 优先 / 账号密码兜底） × MetaMask 钱包初始化 × 行为随机化 × 自动养号。

---

## 一、功能总览

| 能力 | 说明 |
| --- | --- |
| 批量执行 | 通过 ixBrowser 本地 API 依次打开已建好的窗口（每个窗口独立 IP / 环境），一个窗口处理完再开下一个 |
| Twitter 登录 | 每条记录先注入 `auth_token` 登录；失败后自动改用「账号 + 密码」登录，需要时自动填入 2FA 验证码 |
| 结果记录 | 同时写入 Excel（新增状态列）与本地 SQLite（`data/state.db`），GUI 可直接查询每条记录的两种登录结果 |
| 钱包初始化 | 登录成功后，自动生成 12 词助记词并导入 MetaMask，记录地址 / 助记词 / 钱包密码；可切换为纯人工模式；**支持一键下载并自动加载 MetaMask 扩展（`--load-extension`），无需在 ixBrowser 逐个窗口手动安装** |
| 行为随机化 | 打乱账号 / 窗口顺序、账号间随机等待、分批长休息、限制单次数量、登录前访客浏览，降低批量特征 |
| 自动养号 | 按账号随机浏览时间线、阅读推文、点赞、转推、收藏、看视频、关注、搜索，可设每日次数与时段 |
| 图形界面 | 所有运行参数在界面修改，点“开始”自动保存，无需手改配置文件 |
| 断点续跑 | 已登录 / 全部失败 / 受限的行默认跳过，异常中断的行下次自动重试 |

## 二、功能实现过程

### 2.1 总体流程

```
读取 config.yaml / 界面参数
        │
        ▼
读取 Excel → 得到待处理记录列表（pending）
        │
        ▼
连接 ixBrowser API → 获取窗口列表（可过滤 / 限制数量）
        │
        ▼
┌────────────── 遍历窗口 ──────────────┐
│ 打开窗口 → 拿到 CDP 调试地址          │
│ Playwright 连接到该窗口               │
│                                      │
│ ┌──────── 遍历记录 ────────┐          │
│ │ ① token 登录             │          │
│ │    成功 → 钱包 → 下一条   │          │
│ │    失败 → ② 账号密码登录  │          │
│ │          成功 → 钱包      │          │
│ │          失败 → 标记并换下一条 │      │
│ └──────────────────────────┘          │
│                                      │
│ 关闭窗口 → 下一个窗口                  │
└──────────────────────────────────────┘
        │
        ▼
保存 Excel + 输出统计汇总
```

### 2.2 单个窗口内的一次登录判定

**第一步：token 登录**

> 原理说明：这一步与 Chrome 插件「X-token-login」的实现完全一致——都是把 `auth_token`
> 写入 `x.com` 的 Cookie 后刷新页面。插件只是把该动作做成了可视化输入框，
> **不会降低** token 被风控识别的概率。真正的风险来自：token 来源 IP 与窗口 IP 不一致、
> 同一 token 在多个窗口重复使用、以及短时间高频登录。

1. 清除浏览器上下文里的 `auth_token` / `ct0` / `twid`；
2. 写入表中 token（若配置了 ct0 列则一并写入）到 `.x.com` 域；
3. 打开 `https://x.com/home`，在超时时间内反复探测：
   - 出现侧边栏账号按钮 → **成功**；
   - 跳到 `/i/flow/login` 或页面同时出现 Log in / Sign up → **失效**；
   - 跳到 `/account/access`、`/i/flow/verify`、手机验证页，或页面出现 suspended / verify your identity → **受限**；
   - 网络异常、页面打不开 → **异常**（按配置重试 1 次）。
4. 成功时顺带从侧边栏链接读取 `@用户名`。

**第二步：账号密码兜底（token 未成功且未受限时）**

1. 再次清除登录 Cookie，打开 `https://x.com/i/flow/login`；
2. 填账号 → 回车；
3. 等待密码框，期间若出现「补充手机号/邮箱」「异常活动」「确认身份」→ 直接判定 **受限/需人工**（不硬试）；
4. 填密码 → 回车；
5. 若出现验证码输入框，则：
   - 从记录的 2FA 链接中取出 `key`，**本地按标准 TOTP（30 秒 / 6 位 / SHA1）计算验证码**，无需访问该网站；
   - 链接里没有可用 key 时，才退化为抓取网页上的 6 位数字；
   - 最多输入 2 次；
6. 判定成功 / 密码错误 / 受限 / 超时异常。

**第三步：钱包（仅登录成功时）**

1. `auto` 模式：本地生成 12 词助记词 → 推导地址 → 生成随机密码 → 通过 Playwright 在 MetaMask 插件页面完成导入；
2. 导入失败：截图保存到 `screenshots/`，按配置转为人工回填；
3. `manual` 模式：只提示，人工在窗口内创建后回填；
4. `skip` 模式：本次不处理钱包。

**第四步：写结果**

- Excel：写 `token登录` / `账号登录` / `最终结果` / `状态` / 窗口信息 / `X用户名` / 钱包三列 / `处理时间` / `备注`；
- SQLite：`data/state.db` 中按 Excel 行号记录同样的信息，供 GUI 查询。

### 2.3 停止机制

界面点“停止”只是设置一个停止事件：当前窗口的当前步骤会走完，然后在该窗口结束时退出，已处理的结果都会保存。

### 2.4 行为随机化（登录流程）

```
读取记录 → 随机打乱顺序 → 截取本次数量（daily_limit）
        │
        ▼
窗口列表 → 序号范围过滤 → 可选打乱 → 数量限制
        │
        ▼
打开第 1 个窗口（可选：先访客浏览 5~15 秒）
        │
        ▼
处理完 → 随机等待 20~90 秒 → 下一个窗口
        │
        └─ 每处理 N 个窗口 → 随机长休息 5~15 分钟
```

- 目的是打散「固定顺序 + 固定间隔 + 一次性跑完」这三个最明显的机器特征；
- 随机化只改变节奏，不改变判定逻辑和结果；
- 与序号范围同时使用时，建议关闭「打乱窗口顺序」，否则序号失去意义。

### 2.5 养号流程

```
筛选账号（已登录 / 未使用，且今天未达次数）
        │
        ▼
随机挑选 N 个 → 按 Excel 的“窗口ID”绑定窗口（没有则取空闲窗口）
        │
        ▼
打开窗口 → token 登录（或直接检查已有登录态）
        │
        ▼
随机动作循环，直到达到本次时长或动作上限：
  滚动时间线 / 打开推文阅读 / 点赞 / 转推 / 收藏 /
  看视频 / 侧边栏关注 / 关键词搜索 / 看自己主页
        │
        ▼
写 SQLite 养号记录 + Excel「养号次数 / 最后养号时间」
        │
        ▼
随机休息 1~4 分钟 → 下一个账号
```

动作概率、单次上限、停留时长、每日次数全部可配；每个号每天默认只跑 1 次。

```

├─ modules/

│  ├─ ext_install.py      # 下载并解压 MetaMask 扩展（Chrome 商店 / GitHub）
│  ├─ tw_login.py         # token 登录判定 + 账号密码登录（含 2FA）
│  ├─ twofa.py            # TOTP 本地计算 / 网页抓取兜底
│  ├─ humanize.py         # 拟人化等待 / 随机滚动 / 阅读停留
│  ├─ warmup.py           # 养号：浏览、点赞、转推、收藏、关注、搜索

│  ├─ state_db.py         # SQLite 记录库（登录记录 + 养号记录）
│  └─ wallet.py           # 助记词生成、MetaMask 自动导入、截图
├─ extensions/metamask/   # 下载后生成，含 manifest.json（自动加载用，勿移动）
├─ data/state.db          # 运行后自动生成
├─ logs/                  # 运行日志（每次一个文件）
└─ screenshots/           # 钱包失败截图
```

## 四、环境准备与安装

### 4.1 前置条件

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 |
| Python | 3.10 及以上，安装时勾选 **Add python.exe to PATH** |
| ixBrowser | 客户端已安装并登录，本地 API 默认 `127.0.0.1:53200` |
| 窗口 | 已建好 N 个窗口，且每个窗口配置了不同代理 IP |
| 数据表 | Excel，至少包含 `token`、`账号`、`密码`、`2FA` 四列 |

### 4.2 安装步骤

1. 解压 `x-batch.zip` 到任意目录（例如 `E:\x-batch`），**确认 `gui.py` 就在这一层**；
2. 双击 `install_deps.bat`，等待出现 `Install finished`；
   - 若官方源失败会自动改用清华镜像；也可手动执行：
     ```bat
     python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
     ```
3. 双击 `run_gui.bat` 启动界面（窗口标题会显示版本号）。

## 五、Excel 数据说明

### 5.1 输入列（只读这几列）

| 列名（默认，可在界面改） | 含义 | 说明 |
| --- | --- | --- |
| `token` | Twitter auth_token | 兼容 `auth_token=xxx`、JSON、裸值三种写法；列名找不到时会自动匹配含 token 的列 |
| `账号` | 用户名 / 邮箱 / 手机号 | 不要带 `@`，脚本会自动去掉 |
| `密码` | 账号密码 | token 失败后使用 |
| `2FA` | 验证码链接或密钥 | 形如 `https://2fa.xdgongju.top/?key=XXXX`，取 `key` 本地计算 |
| `ct0`（可选） | csrf token | 表中存在且配置了列名才会写入 |

> 邮箱 / 邮箱密码等其它列会被忽略，不会读取也不会修改。
>
> 没有现成表格时，可在「① Excel」点 **下载登录模版**，按当前列名生成一份标准表（另附「填写说明」页），填好数据后直接选用。

### 5.2 输出列（自动追加）

| 列名 | 取值 |
| --- | --- |
| `token登录` | 成功 / 失效 / 受限 / 异常 / 未尝试 |
| `账号登录` | 成功 / 失败 / 受限 / 异常 / 未尝试 |
| `最终结果` | 已登录 / 全部失败 / 受限/需人工 / 异常 |
| `状态` | 与“最终结果”一致（保留旧字段，便于脚本兼容） |
| `窗口ID` / `窗口名称` | 处理该条记录时使用的 ixBrowser 窗口 |
| `X用户名` | 登录成功后读取到的 `@handle` |
| `钱包地址` / `助记词` / `钱包密码` | 钱包初始化结果（`auto` / `manual` 模式） |
| `处理时间` | 该行最后一次更新时间 |
| `备注` | 失败原因、登录方式、钱包异常信息等 |
| `养号次数` / `最后养号时间` | 养号脚本每次成功运行后累加 / 更新 |

> 养号的详细动作统计（点赞、转推、关注、时长）存在 `data/state.db` 的 `warmup_log` 表，不占 Excel 列。

### 5.3 断点续跑规则

- **会处理**：状态为空、`未使用`、`异常`、`未处理`；
- **会跳过**：`已登录`、`全部失败`、`受限/需人工`；此外 `token登录` 列为 `成功` 的行也会跳过——即便 `状态` 仍为空（如上一轮在写状态列前被中断），已成功注入的 token 不会被重复使用；
- **窗口级跳过**：打开窗口后会先用 `check_session` 检测窗口内是否已有 X 登录态，已有则直接跳过本窗口（不注入 token、不覆盖现有会话），该行 token 留给其他窗口，统计中计入「已登录跳过」；
- 想重跑某些行：把对应行的 `状态` 与 `token登录` 列都清空即可；
- 首次写入前会生成 `原文件名.bak` 备份（可在界面关闭）。

## 六、使用手册（图形界面）

### 6.1 页签说明

**① Excel**

| 参数 | 说明 |
| --- | --- |
| 表格路径 | 支持相对/绝对路径，右侧可浏览选择 |
| token 列名 | 默认 `auth_token`，找不到会自动匹配 `token` |
| ct0 列名 | 可留空 |
| 账号列名 / 密码列名 / 2FA 链接列名 | 默认 `账号` / `密码` / `2FA`；关闭账号密码登录后自动置灰，无需填写 |
| 工作表名 | 留空 = 第一个工作表；多 Sheet 时填写目标表名 |
| 行号范围 | 只处理该 Excel 行号区间内的记录（0 = 不限） |
| 备份原表 | 首次写入前生成 `.bak` |
| 仅重跑失败/受限/异常行 | 勾选后只处理上次 全部失败 / 受限 / 异常 的行 |
| 下载登录模版 | 按当前列名生成标准表头 + 填写说明页，另存到指定位置 |
| 下载执行结果 Excel | 运行结束后另存一份结果副本（优先取最近写入的 `*_results`），原表不改动；运行中不可用 |
| 重置失败行 | 清空失败/受限/异常行的 状态 / 最终结果 / token登录 / 账号登录，原始 token 不受影响；运行中不可用 |

**② ixBrowser**

| 参数 | 说明 |
| --- | --- |
| API 地址 / 端口 | 默认 `127.0.0.1` / `53200` |
| 窗口名称关键字 | 只处理名称包含该关键字的窗口，留空为全部 |
| 窗口序号范围 | 起始 ~ 结束（1 开始，按窗口列表顺序；结束填 0 = 到最后一个），用于手动指定只跑某几个窗口 |
| 最多处理窗口数 | `0` 表示不限制；与序号范围叠加生效 |
| 处理完不关闭窗口 | 调试用 |

> 点「测试连接」会弹出窗口列表并标注序号，可据此填写序号范围。

**③ Twitter**

| 参数 | 说明 |
| --- | --- |
| 登录超时 | 注入 token 后等待判定的时间（秒） |
| 单窗口最多处理记录 | 防止一个窗口把整表跑完 |
| 异常重试次数 | 网络类错误对同一 token 的重试次数 |
| 动作间隔 min / max | 每个动作间的随机延迟（秒），降低风控概率 |
| 启用账号密码登录 | 关闭后 token 失败即标记失败 |
| 账号密码登录超时 | 整个账号密码流程的总超时（秒） |

**④ 钱包**

| 参数 | 说明 |
| --- | --- |
| 启用钱包 | 关闭则只登录 |
| 模式 | `auto` 自动导入 / `manual` 人工 / `skip` 跳过 |
| 扩展 ID | 留空自动探测 |
| 自动加载扩展 | 开窗口时用 `--load-extension` 加载本地 MetaMask（推荐） |
| 扩展目录 | 解压后的扩展路径，默认 `extensions/metamask`；右侧「选择」可改 |
| 下载 / 安装 MetaMask | 一键从 Chrome 商店 / GitHub 下载并解压到扩展目录；网络不通时点旁边「导入本地扩展包」选择已下载的 `.zip` / `.crx` |
| 密码前缀 / 长度 | 留空「统一钱包密码」时，按此前缀+长度随机生成 MetaMask 密码 |
| 统一钱包密码 | 非空时所有钱包都用该密码（默认 `wyt000930zz`）；留空则按前缀+长度随机生成 |
| 单步超时 | 每一步 UI 操作的等待时间（秒） |
| 失败转人工 | 自动导入失败时，先把失败原因写入日志并截图，再弹窗等待人工回填（不再阻塞控制台） |

**⑤ 随机化**

| 参数 | 说明 |
| --- | --- |
| 打乱待处理账号顺序 | 每次运行随机排列记录，避免固定顺序 |
| 打乱窗口顺序 | 与序号范围同时使用时建议关闭 |
| 账号之间随机等待 | 两个窗口之间的随机间隔（建议 20~90 秒） |
| 每 N 个窗口后长休息 | 0 = 不休息；例如每 5 个窗口休息 5~15 分钟 |
| 本次最多处理记录数 | 0 = 不限；配合多天分批跑 |
| 登录前先访客浏览 | 注入 token 前先浏览 5~15 秒，减少“开窗即登录”特征 |

**⑥ 养号**

| 参数 | 说明 |
| --- | --- |
| 启用养号功能 | 关闭后「开始养号」会拒绝执行 |
| 登录方式 | `auto` 有 token 用 token；`session` 只用窗口已有登录态 |
| 单号停留时长 | 每个账号本次停留的随机区间（秒），建议 120~300 |
| 本次养号账号数 / 每号每天次数 | 0 = 全部符合条件的账号；每天默认 1 次 |
| 滚动后停留 / 最多滚动 | 浏览节奏参数 |
| 点赞 / 转推 / 关注概率与上限 | 单次会话最多做几次，避免动作过量 |
| 视频 / 搜索 / 主页概率 | 触发概率（百分比） |
| 搜索关键词 | 逗号分隔，留空则不搜索 |
| 允许运行时段 | 如 `9-23`，留空 = 不限；配合计划任务使用 |
| 账号间隔休息 | 两个账号之间的随机休息（秒） |

> 养号按钮在 ⑥ 页签内（「🌱 开始养号」），与顶部「开始」共用停止与日志区。

**⑦ 记录查询**

- 数据来自 `data/state.db`，与 Excel 相互独立，Excel 被占用也能查；
- 支持关键字搜索（账号 / 序号 / 窗口 / 备注）、按最终结果筛选，以及按 `YYYY-MM-DD` 日期范围筛选；
- 颜色：绿色=已登录，红色=全部失败，橙色=受限/异常；
- 顶部显示各状态汇总数量；每次运行结束自动刷新；
- 「导出 Excel」把当前查询结果另存为表格；
- 双击某行会打开该窗口最新的钱包失败截图（`screenshots/wallet_fail_*<窗口名>*.png`），没有截图则打开截图目录。

### 6.2 操作步骤

1. 在「① Excel」选择表格，确认四个列名与表头一致（还没有表格可先点 **下载登录模版** 生成一份）；
2. 在「② ixBrowser」确认客户端地址与端口，点击右上角 **测试连接**，应显示可用窗口数；
3. 在「③ Twitter」按需调整超时与延迟；
4. 在「④ 钱包」选择模式（不想动钱包就选 `skip`）；首次使用点「下载 / 安装 MetaMask」（或运行 `install_metamask.bat`），等状态显示「✓ 已就绪」；下载失败时，点「导入本地扩展包」选择已下载的 `.zip` / `.crx` 离线安装；
5. 在「⑤ 随机化」按需开启打乱与分批休息；
6. 点击顶部 **开始**：
   - 参数会自动写回 `config.yaml`（运行中参数与保存/加载按钮会锁定，停止后恢复）；
   - 日志区实时滚动，右侧统计与进度条（`进度 x/y`）实时更新；
7. 需要中断点 **停止**；
8. 结束后会弹出汇总，可点右侧「打开结果表 / 日志目录 / 截图目录」快速定位；
9. 想看单个窗口的钱包失败截图，在「⑦ 记录查询」双击对应行；
10. 养号：切到「⑥ 养号」设置参数，点 **🌱 开始养号**，日志区会逐个账号输出动作与统计。

### 6.3 结果核对顺序

```

        ↓
Excel 对应行（看具体备注、钱包信息、养号次数）
        ↓
logs/run_*.log（登录过程） / logs/warmup_*.log（养号过程）
```

## 九、注意事项

### 9.1 登录相关

1. **token 与账号密码是串联关系**：token 成功即结束，不会再用账号密码；token 受限时也不会硬试密码，直接标记 `受限/需人工`。
2. **账号密码登录依赖 X 当前页面结构**；若 X 改版，可能出现找不到输入框的超时，表现为 `异常`，需要更新选择器。
3. **2FA 按标准 TOTP 计算**（30 秒周期 / 6 位 / SHA1）。如果某站点不是标准实现，验证码会不对，可反馈后把周期或位数做成参数。
4. **风控**：账号密码登录比 token 更容易触发异常活动验证，表现为 `受限/需人工`，属正常保护，不建议频繁重试。
5. 延迟参数不要设得太小（建议 ≥2 秒），窗口切换过快更容易被风控。

### 9.2 Excel 相关

6. **运行前关闭 Excel/WPS 打开的表**。被占用时程序仍能跑，但结果只能写到 `xxx_results.xlsx`，不会写回原表。
7. 首次写入会生成 `.bak` 备份；如果表很大，备份会占空间。运行结束后可用「① Excel → 下载执行结果 Excel」另存副本用于交付或归档：该操作只复制文件，不改动原表，任务运行中按钮不可用（避免读到写入一半的文件）。
8. 表头文字必须和界面里的列名一致（默认 `token` / `账号` / `密码` / `2FA`），否则会提示找不到列。
9. 想重跑已处理行：清空该行 `状态` 列。

### 9.3 窗口与记录

10. 一个窗口默认最多消耗 20 条记录（`max_tokens_per_profile`），避免单个窗口承载过多账号。
11. 窗口会按列表顺序各用一次，不会循环复用；所有窗口跑完仍有剩余记录时，这些记录保持未处理，下次运行继续。
12. 窗口打开失败（客户端未启动、端口不对、窗口被删除）会记 `窗口失败`，不影响后续窗口。
13. 窗口 ID 必须是 ixBrowser 返回的数字 ID，脚本会自动转数字后再调用接口。

### 9.4 钱包相关

14. 助记词、钱包密码、token、Twitter 密码均为**明文**写入 Excel 与本地库，注意文件保管与备份。
15. MetaMask 的自动导入依赖插件版本与页面结构，插件更新后可能失效，失败会自动截图。
16. `manual` 模式在 GUI 下没有控制台输入，无法回填（建议用 `auto` 或直接在窗口内人工完成后手动填表）。

### 9.5 运行环境

17. 脚本**不修改代理**，每条记录走哪个 IP 完全由所在 ixBrowser 窗口决定，请提前把窗口代理配置好。
18. 同一目录不要同时开两个实例，会争抢同一个 Excel 与记录库。
19. 日志在 `logs/run_日期_时间.log`，反馈问题时提供对应日志中 `[ERROR]` 段落。
20. 确认版本：窗口标题、`VERSION.txt` 首行、Release 页面标签三者应一致。

### 9.6 关于浏览器扩展

21. **MetaMask 有三种安装方式，二选一即可**：
    - **自动加载（推荐，v1.4.1+）**：在 GUI「④ 钱包」页签点「下载 / 安装 MetaMask」（或运行 `install_metamask.bat`），脚本会把最新版 MetaMask 解压到 `extensions/metamask/`；之后每次打开窗口都通过 Chrome 的 `--load-extension` 参数自动加载，**无需在 ixBrowser 里逐个窗口安装**。
    - **本地导入（v1.4.4+，离线可用）**：自行从 Chrome 应用商店或 MetaMask GitHub Release 下载扩展包（`.zip` / `.crx`），在「④ 钱包」点「导入本地扩展包」选择该文件即可解压安装，不依赖网络。
    - **手动安装**：在 ixBrowser 客户端里为窗口安装 Chrome 商店扩展，窗口多可用「扩展同步」统一分发；此时请在配置里把 `auto_load_extension` 关掉，避免重复加载。
22. 自动加载的扩展，扩展 ID 由**本地目录的绝对路径**派生。**不要移动 `extensions/` 目录**，否则各窗口里已有的钱包会因 ID 变化而重置（钱包数据仍在窗口里，但变成一个新的空 MetaMask）。
23. 安装 MetaMask 后无需手动创建钱包，脚本会自动导入；窗口里已有钱包时会标记 `exists`，不会覆盖。
24. **不建议改用 X-token-login 插件登录**：其原理与本脚本相同（写 `auth_token` Cookie），不会提升稳定性，反而多了一层人工输入，无法批量执行。
25. 降低风控的有效手段是：一窗口一 token、窗口代理地区与 token 来源一致、保持 3~6 秒随机延迟、避免同一时间批量登录大量账号。

### 9.7 随机化与养号

26. 随机化只改变节奏，不保证通过女巫检测；真正的聚类风险仍来自**链上资金同源**（同一地址打 gas、账号互转、归集）与设备指纹。
27. 养号动作是「轻量互动」：不发文、不改资料、不发私信、不关注大量账号，避免触发平台风控。
28. 养号依赖 X 页面结构（`data-testid`）；若 X 改版，动作会失败并记录在日志里，需更新选择器。
29. 每个窗口的 IP 由 ixBrowser 代理决定；养号时尽量保持「账号 - 窗口 - 代理地区」一致，不要频繁换窗口。
30. 建议节奏：每天固定时段跑一次、每号 2~5 分钟、点赞上限不超过 6、转推与关注尽量少（更接近真人）。
31. 养号记录写入 `data/state.db` 的 `warmup_log` 表；清空该表即可重跑当天的额度。

| 养号动作全部失败 | X 页面结构变化 | 查看 `logs/warmup_*.log`，更新 `modules/warmup.py` 选择器 |

## 十一、常见问题

**Q1：token 登录和 X-token-login 插件有区别吗？会不会更容易被检测？**
没有区别。两者都是把 `auth_token` 写入 x.com 的 Cookie 后刷新页面，插件只是提供了输入框。
是否被检测取决于 token 与窗口 IP 是否匹配、是否跨窗口复用 token、登录频率，而非写入方式。

**Q2：只跑 token，不跑账号密码，表里要准备哪些列？**
只需 `token` 一列（表头名可在界面改）。在「③ Twitter」取消勾选「改用账号密码登录」，
「① Excel」里的账号/密码/2FA 列名会自动置灰，不参与读取。

**Q3：怎么只跑指定的几个窗口？**
在「② ixBrowser」填写序号范围，例如 `5 ~ 12`；先点「测试连接」查看窗口与序号的对应关系。
序号按 ixBrowser 窗口列表顺序（一般是创建顺序）。

**Q4：钱包是用 MetaMask 插件创建的吗？后续能用来连接网站吗？**
是。脚本在窗口内驱动真实的 MetaMask 扩展完成导入，钱包保存在该窗口的扩展里，
后续可直接在该窗口连接网站。助记词、地址、密码会同时写入 Excel 与本地记录库。

**Q5：多开窗口的 IP 由谁决定？**
由 ixBrowser 窗口自身的代理配置决定，脚本不修改代理。请确保窗口代理与 token 所属地区尽量一致。

**Q6：随机化之后还会被判女巫吗？**
随机化只能降低「行为节奏」这一类特征。如果多个账号由同一地址打 gas、互转资金、
或设备指纹高度一致，仍会被聚类。请优先做好资金隔离与指纹隔离。

**Q7：养号会不会被 X 判定为自动化？**
养号只用浏览器内的常规点击与滚动，节奏随机、动作量小。但任何自动化都有风险，
建议控制频率（每天 1 次、每次几分钟），不要所有账号同一秒开始。

**Q8：养号需要 token 吗？**
`login_mode=auto` 会用表里的 token 登录；`session` 模式则直接复用窗口里已有的登录态，
适合已经在窗口里手动登录过的账号（这类账号需要有 `窗口ID` 才能在表里对应上）。

**Q9：养号能中途停止吗？**
可以。点顶部「停止」，当前动作会走完，然后保存记录并退出；已跑的账号不会重复计入当天次数。
